# XDPoS Mixed-Client Debugging Exercise

Welcome to the XDPoS mixed-client debugging exercise.

This is a hands-on debugging task involving a local XDC/XDPoS network and a modified Geth client.

## Before you start

Please read:

1. **[CANDIDATE-BRIEF.md](./CANDIDATE-BRIEF.md)** — exercise background, objectives, expectations, and submission requirements.
2. **[RUNBOOK.md](./RUNBOOK.md)** — setup and execution instructions.

## What you'll do

You will:

- Build the provided Geth client from source.
- Start the provided local network.
- Observe and diagnose the consensus behavior.
- Identify the underlying issues in the Geth implementation.
- Fix the problems.
- Verify the network after your fixes.
- Run the provided tests.
- Document your findings and evidence.

You are **not expected to have prior XDPoS knowledge**. The Candidate Brief provides the background needed for the exercise.

## Expected time

Approximately **2–3 hours**.

## Requirements

- **Linux or macOS** — on Windows, use **WSL2** (the harness is bash)
- **Go 1.24+**
- **python3**
- Git, curl, and standard build tools
- ~4 GB free RAM and ~2 GB disk
- Internet access for the initial setup

Full details and version checks are in [RUNBOOK.md](./RUNBOOK.md).
