# XDC Consensus-Parity Audit — Coverage Report

Generated by an adversarial multi-agent audit (9 agents) driving the
`xdc-conformance` harness against the **live** XDC mainnet and apothem networks
on 2026-06-21, then re-verifying every anomaly. The harness reuses this repo's
own `core/types` (and `core/forkid` / `params`), so its hashing, seal-recovery,
QC-quorum and fork-ID logic is the canonical consensus code, not a re-spec.

## Anomalies — all root-caused to non-consensus causes (none were real)

1. **gate D false-FAIL on the early-apothem-v2 window (blocks 56,828,701+,
   rounds 1–12).** Root cause was a **harness defect, not a chain divergence**:
   gate D used a hardcoded ≥2/3 quorum, but apothem's V2 config uses a
   **round-keyed `CertThreshold = 0.45` for rounds 0..899,999** (then 0.667).
   The canonical engine requires ⌈13 × 0.45⌉ = 6 signers; the 7 in-set signers
   are a valid quorum. **Fixed**: gate D now reads `params.XDC*ChainConfig.XDPoS.V2.Config(qcRound).CertThreshold`
   (after `BuildConfigIndex()`), so the threshold matches the engine per round.
   Post-fix these blocks PASS (`certT=0.450 threshold=6`), and later blocks
   still PASS at `certT=0.667` with no regression.
2. **gate D "FAIL" at the V2-switch bootstrap (mainnet 80,370,001 / apothem
   56,828,701), qcSigs=0.** This is the synthetic round-0 epoch-switch QC — the
   first v2 block has no prior v2 round to vote on, so `verifyQC` skips the
   CertThreshold check. **Fixed**: gate D now recognises a round-0 QC and skips
   the quorum check (reports `bootstrap-QC`), matching the engine.
3. **SKIP at exact V1/V2 switch blocks** (`extra[0] != 0x02`) — correct, those
   are still V1.
4. **"no such block" near tip** — public-RPC history-pruning / load-balancer
   gaps; re-probed served blocks PASS.
5. **v1 M2 `in=false`** — informational secondary-signer reports (the #951
   diagnostic field), not M1 seal-recovery failures (see gate C notes).

## Scope / not covered

- **Deep-history `stateRoot` proofs are not verified** — public RPCs are
  state-pruned and reject `eth_getProof` (`stateRoot-proof[n/a]`). Gate G's
  proof check is validated at the tip on a full node; deep-history coverage
  needs an archive node exposing `eth_getProof` (fleet currently runs only
  `gcmode full`).
- **Full EVM state-transition re-execution (post-state root per block) is not
  covered here** — that is the client port's own execution work (spec M4 / gate
  12-E full form), out of scope for this header/consensus-shape audit.
- **Sampling, not exhaustive replay** — adversarial spot-sampling at fork
  boundaries and across eras. The `0x..90` (RandomizeSMC) gasless case was not
  observed in the recent scan window; only `0x..89` (BlockSigners) was
  exercised.
