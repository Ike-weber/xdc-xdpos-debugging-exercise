# net5050 support in the one-command installer

`scripts/one.sh` (v1.2.0) + `scripts/clients.d/*.sh` are the source of the
installer served at `https://xdc.network/install.sh` → `one.sh`. This document
records the net5050 (chainId **5050** / `0x13ba`) support added across all six
clients and the validated per-client status.

## Usage

```bash
curl -fsSL https://xdc.network/install.sh | bash -s -- --client <c> --network net5050
```
`<c>` ∈ `geth | xone | erigon | reth | nethermind | besu`. The installer forces
**full-sync from genesis** for net5050 (see #96 below) — net5050 is small
(~361k blocks), so full sync reaches tip in ~15–40 min on small storage.

## What was added

- **Capability gate:** net5050 added to `CI_NETWORKS` for all six clients (was
  present only for reth) — previously the installer `exit 1`ed before doing
  anything for the other five.
- **Genesis:** `scripts/net5050-genesis.json` (chainId 5050, genesis
  `0x3f63fcc4…`, V2 switch @2700) is hosted at `xdc.network/snapshots/` and
  auto-`init`ed by each client (geth/xone/erigon/besu via genesis-file init;
  nethermind via its embedded `xdc-net5050` chainspec; reth via `--chain
  xdc-net5050`).
- **Chain selector:** `CHAIN_FLAG="--networkid 5050"` for net5050 (no built-in
  `--net5050` flag exists); geth `init` uses `--state.scheme "$SCHEME"` so the
  init'd DB scheme matches start.
- **Mode override:** any requested `--mode fast|snap|minimal` is forced to
  `full` for net5050 (#96 — net5050 peers serve no snap/fast state).
- **Static peers:** the five net5050 validator enodes (xdc04/xdc05 fleet +
  bootnode) are wired per client to defeat the fresh-node peers=0 handshake gap
  (#131) — validated to bring peers 0 → 3–4.
- **ethstats:** wired for the geth-family clients so installed net5050 nodes
  appear on `stats.xdcindia.com` as `<host>-net5050-full-<os>`.

## Validated per-client status (live e2e on a net5050-connected host)

| Client | Reaches net5050 tip (small storage) | Visible on stats.xdcindia.com |
|---|---|---|
| **geth** | ✅ chainId 5050, peers 3, head climbing | ✅ ethstats wired |
| **xone** | ✅ chainId 5050, head climbing (`-override.genesis`) | ✅ ethstats wired |
| **nethermind** | ✅ chainId 5050, peers 4, head climbing | ✅ native EthStats plugin (wss) |
| **reth** | ✅ chainId 5050, peers 4, head climbing | ❌ see ceiling below |
| **erigon** | ✅ chainId 5050, peers, head climbing | ❌ no ethstats client |
| **besu** | ⚠️ installs + chainId 5050, but **peers 0** | ❌ no ethstats flag |

## Known ceilings (client-binary limits, beyond the installer)

- **reth stats:** reth-xdc hardcodes `ws://` for `--ethstats` while
  `stats.xdcindia.com` accepts only `wss://` (connecting crashes the node).
  Needs a reth-xdc code fix; `--ethstats` is deliberately **not** wired for reth.
- **erigon / besu stats:** neither binary ships a native ethstats client — a
  standalone sidecar reporter would be required for dashboard visibility.
- **besu peering:** besu speaks `eth/100 + snap/1` while the net5050 fleet
  speaks `xdpos2/100` exclusively — besu cannot peer on net5050 until the
  XDPoS2 handshake is ported (XDCIndia/besu#29). The installer wires the branch
  but the node will stay at peers 0.
